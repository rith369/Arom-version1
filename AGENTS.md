# AROM — Project Instructions & Guidelines

## 1. Project Overview
- **Product:** AROM (អារម្មណ៍), a bilingual (English & Khmer) mental health and emotional wellness web platform.
- **Repository:** https://github.com/rith369/Arom-version1
- **Core Features:** Emotion/wellness detection, Mindguide, practice exercises, learning modules, community, and professional booking.

## 2. Tech Stack & Libraries
- **Framework:** Next.js 16 (App Router, React 19)
- **Styling:** Tailwind CSS v4 (`@tailwindcss/postcss`) + CSS custom utilities
- **Animations:** Motion (`motion/react` / `motion`)
- **Icons:** `lucide-react`
- **Forms & Validation:** `react-hook-form` + `zod`
- **Typography:** Inter (Latin) & Kantumruy Pro (Khmer)

## 3. Essential Commands
- `npm run dev`: Start local development server (port 3000)
- `npm run build`: Production build check
- `npm run lint`: Run ESLint checks

## 4. Coding & Architecture Standards
- **Component Placement:**
  - Route pages reside inside `app/<feature>/page.tsx`.
  - Shared global components & providers reside in `app/_components/` (e.g., `language-provider.tsx`, `detection-provider.tsx`).
  - Route-specific components are grouped within feature subdirectories.
- **Bilingual & Localization:** Always support or consider English and Khmer text rendering with proper font classes (`font-sans`, Kantumruy Pro).
- **TypeScript:** Strict typing — avoid `any`. Use descriptive interfaces and prop types.
- **Styling Rules:** Ensure mobile responsiveness and accessible contrast suitable for a calming wellness aesthetic.

## 6. Punctuation & Copywriting Guidelines (Strict Anti-AI Text Style)
- **NEVER use em dashes (—), en dashes (–), or loose hyphens (-) in text, descriptions, titles, translations, or UI copy.** They look robotic and AI-generated.
- **Use commas (,), periods (.), parentheses (()), or colons (:) instead.**
- **Bilingual Phrasing:** Place the natural Khmer term first followed by the English equivalent in parentheses, for example: `ភាពតានតឹង (Burnout)` or `ការថប់បារម្ភ (Anxiety)`. Never use a dash to separate translations.

## 7. Anti-AI Icon Standard: No Sparkles or 4-Point Star Icons
- **NEVER use the 4-pointed star or sparkles icon (`Sparkles`, `Sparkle`, or similar AI-style star graphics) anywhere in the application.** Users immediately identify this symbol as generic AI.
- **Use human, clinical, and calming wellness icons instead:**
  - For insights or progress summaries: use `Compass`, `Activity`, `HeartPulse`, or `FileText`.
  - For completed sessions: use `Activity`, `CheckCircle2`, or `Award`.
  - For takeaways or key points: use `CheckCircle2`, `Bookmark`, or `Lightbulb`.
  - For booking or sessions: use `Calendar` or `CalendarCheck`.

## 8. Change Reporting Standard: Always Update `report.md`
- **Whenever you make a meaningful change or commit code, you MUST document it in `report.md` immediately.**
- **Format:** Match the BrachNha change report style:
  - Heading: `## [Date]: [Title of What Changed]`
  - Commit line: `Commit \`[hash]\`. [Any migration or database notes].`
  - `**Why.**` Plain-language explanation of why the change was made, who it serves, and what problem it solves.
  - `**What changed for users:**` Bulleted list with bold summaries describing real user experience changes.
  - `**What changed for the team:**` Bulleted list with bold summaries explaining developer/team impact.
  - `**What to re-test:**` Step-by-step checklist of specific test actions to verify the feature works.
- Keep newest entries first at the top of the log.

## 9. Privacy, Security & Data Protection Standards (Mental Health Priority)
- **User Privacy & Confidentiality First:** AROM is a mental health and emotional wellness platform. User journals, mood logs, emotional detection scores, voice notes, and professional therapy bookings contain sensitive personal information. They must be treated with clinical grade confidentiality.
- **Strict Row Level Security (RLS):** When creating or interacting with database tables (Supabase/PostgreSQL), Row Level Security (RLS) must always be enforced for production tables. Users must only ever have permission to read, insert, or update their own personal entries. No user should ever be able to query or see another user's private reflections, mood logs, or booking details.
- **Environment Variable Protection:** Never expose secret server keys (such as `SUPABASE_SERVICE_ROLE_KEY` or private API tokens) in client side components or public bundles. Always use public anon keys (`NEXT_PUBLIC_SUPABASE_ANON_KEY`) for browser operations and keep privileged keys strictly in server side handlers.
- **No Sensitive Logging:** Never log raw user journals, personal reflections, vulnerability states, or emotional responses to browser consoles or external third party analytics.
- **Data Minimization:** Only request and persist the minimum personal data required for the user's wellbeing journey.
